# 📖 গল্পে গল্পে System Design

> তানহা নামে এক ছাত্রী হলের রুমে বসে একটা নোট-শেয়ারিং অ্যাপ বানায়।
> ৫ জন user থেকে ৫০ লাখে পৌঁছাতে গিয়ে প্রতিটা ধাপে কিছু একটা ভেঙে পড়ে —
> আর সেই ভাঙা সারাতে গিয়েই একটা একটা করে system design-এর concept আসে।
>
> **কোনো theory মুখস্থ করতে হবে না। শুধু গল্পটা পড়ো।**

## 🎭 চরিত্র

**তানহা** — কম্পিউটার সায়েন্সের ছাত্রী, "পড়ুয়া"-র নির্মাতা। কিছুই জানে না, প্রতিটা জিনিস ভাঙার পর শেখে।

**Boltu ভাই** — তানহার সিনিয়র, একটা কোম্পানিতে কাজ করে। প্রতিটা সমস্যার একটা রোজকার জীবনের উদাহরণ দিয়ে বোঝায়।

**"পড়ুয়া"** — নোট ও প্রশ্নব্যাংক শেয়ার করার একটা ওয়েব অ্যাপ। গল্পের আসল নায়ক।

```
৫ জন user          একটা সার্ভার, সব একসাথে              অধ্যায় ১
    ↓
১৪ হাজার/ঘণ্টা      সার্ভার মরলো → scaling                অধ্যায় ২
    ↓
তিনটা সার্ভার       কে কোথায় যাবে? → load balancer        অধ্যায় ৩
    ↓
অদ্ভুত bug         নিচের স্তর জানা দরকার → protocol       অধ্যায় ৪
    ↓
বিদেশি user        ৮ সেকেন্ড লোডিং → CDN                  অধ্যায় ৫
    ↓
ধীর হোমপেজ         একটা query ৯২% সময় খাচ্ছে → cache     অধ্যায় ৬
    ↓
ডিস্ক ৯২% ভরা      লেখা scale করতে হবে → sharding         অধ্যায় ৭
    ↓
ভোর ৪টার ফোন      হার্ডডিস্ক মরলো → replication          অধ্যায় ৮
    ↓
কেবল কাটা পড়লো     সব একসাথে পাওয়া যায় না → CAP/PACELC   অধ্যায় ৯
    ↓
৫০ লাখ user        সব একসাথে                              অধ্যায় ১০
```

## 💡 কীভাবে পড়বে

**একদম নতুন হলে:** ০ থেকে ১০ — ক্রম অনুযায়ী। প্রতিটা অধ্যায় আগেরটার উপর দাঁড়িয়ে আছে।

**কিছু জানা থাকলে:** যে বিষয়টা দুর্বল, সেই অধ্যায়টা আলাদাভাবেও পড়া যায় — প্রতিটা অধ্যায় স্বয়ংসম্পূর্ণ।

**গভীরে যেতে চাইলে:** প্রতিটা অধ্যায়ের শেষে 📖 চিহ্ন দিয়ে সংশ্লিষ্ট বিস্তারিত নোটের লিংক দেওয়া আছে।
